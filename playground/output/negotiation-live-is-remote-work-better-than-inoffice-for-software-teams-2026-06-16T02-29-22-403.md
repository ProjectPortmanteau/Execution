The real question: "What interaction patterns does this work require, and when?" Not "where should people be?"

I propose **contextual togetherness**: Teams define work by interaction type, then match location/timing to that type. A sprint planning session might be synchronous in-office. Code review might be async-remote. Pair programming on critical systems might be hybrid with scheduled co-location days.

- **Measurement.** How we measure "is this working?" is open. Velocity, quality, retention, learning velocity—trade these deliberately, don't hide them.
- **Transition pacing.** Moving toward contextual togetherness can happen fast or slow depending on team stability.

My non-negotiable: **we decide consciously by interaction type, not ideology.**
